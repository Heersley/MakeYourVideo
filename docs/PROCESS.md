# PROCESS.md — 闭环制片工作方式（单人决策 + 三类专职 AI 协同）

> **定位**：描述「一条片子从选题到交付，人怎么和三个 AI 分工把它做出来」。是流程与协作说明，**不是规范**。
> **裁决顺序**：`AGENTS.md` → `STYLE_B_SILENT_VIBE.md` → 本文件。冲突时以规范为准。
> **适用**：0 人声 · 原生 2K 无声科普短片（`evergreen_vibe`）。

---

## 一、为什么是「1 + 3」

```text
决策者（人 · 四次拍板）
  │
  ├─ ① 选题 ───────► 编导：一手核查 + 隐喻自检 + 分幕/气口/音效 + 执行指令
  │                        │
  ├─ ② 口径定稿 ──────────► 成片工程：阶段 1（720×1280 带 BGM 快审 + 2K 关键帧 + 360px 缩略）
  │                        │
  ├─ ③ 快审验收 ──────────► 成片工程：阶段 2（2K 流式全片 + 6 项验收 + 唯一成片）
  │                        │
  └─ ④ 交付确认 ◄──────────┘
                           ▲
              基建维护 ────┘  规范 / 工具 / 磁盘（不碰成片）
```

三条设计取舍：

1. **决策不外包**：选题、事实口径、快审、交付四项判断只由人拍板，AI 不代替签字。
2. **「想清楚」与「做出来」分离**：编导只产出判断与指令（不写动画代码），成片工程只执行与验收（不改叙事），避免边写边改把分镜带偏。
3. **基建与生产隔离**：基建维护不碰交付目录，成片工程不擅自改规范与公用脚本——改坏了都容易定位。

> 角色是**职责**，不是产品名：编导 / 成片 / 基建可由任意等效工具承担（本文以 LLM 会话 + 编码代理 + 桌面代理为参考实现），关键是**四种职责不合并到同一个会话**。

## 二、角色与边界

| 角色 | 定位 | 核心职责 | 严禁越界 |
|---|---|---|---|
| **决策者（人）** | 导演 / 最终决策 | 定选题与审美；把控四个卡点；审片、验收、发布 | 不跳卡点直接渲全片 |
| **编导** | 事实核查 / 提示词架构 | 切口与钩子；一手核查；隐喻直觉校验；分幕 / 气口 / 音效 / Drop 编排；写可执行的成片指令；成品「现象 → 直接原因 → 根本原因」复盘 | 不编造事实；不无故频繁改规范 |
| **成片工程** | 生产侧 | 读规范 → 写单期 Remotion 持久状态机源码、程序化 PBR 道具与微音效 → 两阶段渲染 → `tools/mix_bgm.py` 出唯一成片 → 6 项验收 → 清理 `.work/` | 不同会长会话连渲多片；未过快审不渲全片 |
| **基建维护** | 规范 / 工具 / 运维 | 维护 `docs/` 与 `tools/`；目录收纳与磁盘清理；模板与示例维护 | 不渲染；不改交付成片；不动他人版本库历史 |

**角色 × 阶段**（`★` 拍板 · `●` 主责 · `○` 参与 · `—` 不介入）

| 阶段 | 决策者 | 编导 | 成片工程 | 基建 |
|---|---|---|---|---|
| [1] 选题 | ★ | ● 提切口 | — | ○ 素材支持 |
| [2] 核查与分镜 | ★ | ● | — | ○ 环境支持 |
| [3] 阶段 1 快审 | ★ | ○ 复核数据 | ● 渲染 | — |
| [4] 阶段 2 全片与验收 | ★ | ○ 读报告 | ● | ○ 磁盘 / 工具 |
| [5] 复盘与演进 | ★ 定方案 | ● 归因 | ○ 现场证据 | ● 落地规范 / 脚本 |

## 三、单条片子的流水线

```text
[1] 选题输入
    • 经典主题直接切入，或从热点里提炼「半年后仍成立」的底层机制
    • 产出：topics/<slug>.md（track / lighting / asset_layers / cut_mode / status / date / duration_tier）
    │  ★ 卡点 1：拍板选题方向
    ▼
[2] 核查与分镜定稿（编导）
    • 一手 URL 核查；物理/力学隐喻自检；档案与公版素材前置
    • 单一视觉母体；精确到 0.1s 的分幕主句流；气口；微音效表；BGM Drop 对齐点
    • 产出：核查清单 + 隐喻自检 + 变量表 + 分幕表 + 音效表 + 完整执行指令
    │  ★ 卡点 2：确认事实口径与分镜定稿
    ▼
[3] 阶段 1 · 低清快审（成片工程）
    • 仅渲染前 25–35s：720×1280 @ 30fps，带 BGM + SFX（mix_bgm --preview-duration）
    • 同批：2K 关键帧静图（道具特写 / 尾迹中段 / 高潮结构）+ 360px 手机缩略拼图
      + 字库生效报备 + seam_delta 表 + 零颤动初检
    │  ★ 卡点 3：确认快审通过；未确认严禁渲全片
    ▼
[4] 阶段 2 · 原生 2K 全片与 6 项验收（成片工程）
    • 1440×2560 @ 60fps 流式直出（High@5.1 / yuv420p / crf 16 / preset slow / -g 120 / +faststart）
    • 定点无损抽帧（120–180 张）测 text_box_diff === 0.000 与 seam_delta
    • tools/mix_bgm.py：前段小节铺底 + Drop 对齐 + --sfx 注入微音效 → 唯一成片 <主题>.mp4（+ src/sfx_only.wav）
    • 6 项验收：编码 / 光场 / ROI 死帧+零颤动+音频断层 / 安全区与联系表 / 事实闭环 / 硬解对拍
    • 全 PASS 后清理本期 .work/
    │  ★ 卡点 4：确认交付
    ▼
[5] 复盘与演进（按需）
    • 编导归因 → 决策者定方案 → 基建集中升级规范与工具链
```

### 四个卡点

| 卡点 | 谁拍板 | 看什么 | 未通过 |
|---|---|---|---|
| 1 选题 | 人 | 半年后还有没有人看；能否被图形演明白 | 退回重选 |
| 2 口径 | 人 | 每个数字有可点 URL；隐喻没画反；Σ 时长在档位内 | 退回补证 / 改分幕 |
| 3 快审 | 人（编导陪看） | 连续丝滑、规则演明白、气口不憋、手机上线看得清 | 回 [2] 改分镜或回 [3] 重出快审，**不渲全片** |
| 4 交付 | 人 | 6 项全 PASS、联系表目视过、许可与声明齐全 | 如实报 FAIL，修复复验 |

## 四、五条协作原则

### 4.1 事实先于一切

所有上屏年份、公式、数值、史料必须有一手可点 URL，统一归档 `facts_and_sources.md`；查不到出处的内容删掉并报告删了什么。

### 4.2 宏观极简、微观精工

单屏单一焦点 + 大留白不变；质感靠四件事：**字**（三档 OFL 字库 + 四段式气口）、**材质**（程序化 PBR + 双层接触投影）、**线**（L1/L2/L3 分级）、**运动**（持久状态机 + Morph / Clean Reset）。

### 4.3 风险前置与资源节约

- 节奏、光效速度、线宽、隐喻方向的问题，前置到分镜核查与阶段 1 拦截——2K 全片返工一次，够做十次快审。
- 指令一步到位：分辨率、安全区、线宽、气口、编码参数、验收命令写全，不留给执行方猜。
- **能局部修就不全量重来**：只改音频 → `-c:v copy` 重混；只错编码 → 重导编码；绝不无故重渲全片。

### 4.4 单条隔离与透明验收

「1 个选题 = 1 条独立视频 = 1 个独立会话」；任何一项验收未过如实报告并复验，禁止静默跳过，禁止「大概没问题」签字。

### 4.5 稳态创作与集中迭代

日常生产在现行规范内打磨内容，**不边做边改规范**；只有识别出制度级或工具级根因冲突时，才走「决策者拍板 → 编导设计 → 基建统一落地」，一次改齐。

## 五、交接物

| 交接 | 载体 | 不传什么 |
|---|---|---|
| 选题 → 编导 | `topics/<slug>.md` | 不做口头补充；字段缺失即停问 |
| 定稿 → 成片 | 一份完整执行指令 + 分幕表 + 音效表 | 不传其它片的分镜 / 帧数据 |
| 快审 → 决策者 | `output/<slug>/review/` 的快审片、关键帧、缩略拼图、`seam_delta` | 不传半成品源码目录 |
| 成片 → 决策者 | 交付目录 7 项 + `decoder_check.json` | 不传 `.work/` 临时帧 |
| 复盘 → 基建 | 复盘档（现象 / 直接原因 / 根本原因 / 改进项） | 不直接改规范，先经拍板 |

**铁律**：只传**文件与结论**，不传上下文垃圾；临时中间物留在 `.work/`，不进交付目录。

## 六、异常与返工

| 现象 | 先判什么 | 处理 | 禁止 |
|---|---|---|---|
| 快审「看着不对」说不清 | 叙事/隐喻 还是 渲染/气口 | 叙事→回 [2]；渲染→回 [3] 重出快审 | 直接渲全片「出来再看」 |
| `text_box_diff ≠ 0.000` | 是否在无损 PNG 上测 | 查 `transform/filter` 残留、坐标是否整数 | 改编码器 / 插全 I 帧压误差 |
| `seam_delta` 尖峰 | 是否非硬切交界 | 查状态机是否被按幕重置 | 用硬切掩盖跳变 |
| ROI 死帧 > 1.80s | 中层图形是否真停 | 加纯几何呼吸 / 摄影机缓推 | 给文字加微晃、开短周期扫光 |
| `decoder_check` FAIL | 灰块 / 档位 / 像素差 | 档位错→重导编码；灰块→查切片 Hack | 用软解结论替代硬解 |
| `bgm_gap_check` FAIL | 正偏移前段是否被留白 | `mix_bgm.py` 铺底重混（`-c:v copy`） | 重渲整片 |
| 磁盘告急 | 谁在占 | 清 `.work/`、旧帧序列、`node_modules/.cache` | `git gc` / `git prune`、删历史成片 |
| 规范自相矛盾 | 版本号与修订日期 | 停下报决策者，以更高版本为准 | 各自按理解执行 |

---

## 七、硬边界

1. 不执行 `git gc` / `git prune` / 强推，不改写他人历史；
2. 不删改他人已交付成片与历史归档；
3. 不用非标编码 Hack（`slice-max-mbs` / 全 I 帧 / 阅读窗像素复制）；
4. 不在未获卡点确认时自动进入下一步；
5. 不把字体、配乐、成片、个人环境配置提交进仓库。
