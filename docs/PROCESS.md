# 单人导演与三类 AI 的协作流程

每个新会话从同一条单期记录接手。角色分工与每次决策的落点如下。

| 环节 | 准备与交接 | 导演判断 |
|---|---|---|
| 策划（无工具卡点） | WorkBuddy / Infra 维护选题池；Gemini / Architect 把可视化命题写进选题卡，完成一手来源、数值与推导，检查物理隐喻与素材版权，写入事实文件、`beats.json` 与单期 `src/manifest.json`。登记节奏例外须给具体幕号、值与理由。 | 在策划对话里确认题材、事实、边界、主句、节奏与例外，再交给 Render。工具不做机械阻断。 |
| review | Codex / Render 接手分幕，执行 preview。快审、关键帧、手机缩略图、抽样证据与收据在 `src/review/`。 | 连续性、可读性、声音、材质与推理是否符合审美。**确认后即可执行 full / ship。** |
| delivery | Render 执行 full、终混、六项验收并归档本次运行证据到 `src/production/`。 | 逐条审片、确认最终交付与分发。 |

程序只强制 `review` 与 `delivery` 两处人工签字。选题与事实阶段以策划对话的结论为准，`approve --gate topic|facts` 仅作历史留痕，不再阻断任何动作；旧单期已写入的记录原样保留。

## 返工与跨会话接手

新会话通过 status 读取下一签字点（`review` → `delivery` → `done`）、未关闭意见与证据。handoff 记下导演原话、接手人、幕号、保护项；接手人用 resolve 附实际文件关闭意见。approve 只登记已获得的导演确认。具体命令集中在 [单片操作手册](PRODUCTION.md)。

- 事实、数值、隐喻有误由 Architect 修订；分幕变化使已签 review 失效，需重新提交样片。
- 文字压图、镜头或动作问题由 Render 修指定幕，检查相邻接缝、阅读窗及保护项，重新提交受影响的快审证据。
- 只需调整混音增益且画面母版与审批摘要匹配时，Render 用 remix 复用母版。源码、时间轴或母版版本改变时，由工具判定需重新制作的环节。
- 多期共性缺陷交 Infra，用可复现输入、实际报告、预期结果描述；修复先验证公共工具，再由后续单期选择新版本。导演负责审美、两次签字（review / delivery）和发布，验证会话应直接读取证据文件。

单期隔离、事实来源及发布要求见 [工程总控](AGENTS.md)。每条片子的制作失败与开放意见留在本期。

## 逻辑角色与本机资源

逻辑角色固定为 Director / Architect / Render / Infra & Verifier，程序卡点固定为 `review / delivery`；角色是职责，不绑定产品名。

本机把 Render 的高精实现集中给 Codex：每期独立 `/new`，负责单期视觉动画、专属材质与音色、布局证据和定向返工，`preview / full` 分步执行。运维与复检交给 WorkBuddy：定时采集、磁盘与恢复包、轻量基建与文档同步、`remix` / `verify` 调度，以及不参与制作的独立只读复检。这样既节省 Codex 额度，也把渲染上下文与日常上下文隔开。两者都不得越过两处人工签字，`output/` 正式出片仍由 Render 侧产出。
