# AGENTS.md — 无声科普生产总控

唯一生产轨道为 `evergreen_vibe`。一张选题卡对应一部无声科普片，采用原生竖屏、程序微音效及配乐。禁止无人值守批量出片、同一长会话连续渲染多片，以及对 `.git` 执行 gc 或 prune。

开工先读本文件和 [视听规范](STYLE_B_SILENT_VIBE.md)。机器规格由本期绑定的 [制作档案](../tools/profiles/) 决定；选题字段、交付目录契约、命令和返工证据见 [单片操作手册](PRODUCTION.md)。依赖按 `package.json` 的 engines、锁文件及工具的生产预检核对；缺项先报告。模型使用 Opus 5.5 或同级。

优先复用 `tools/` 已有能力。新增公用工具需同步 [README 工具索引](../README.md)。`core/vibe/` 由 Infra 维护，新期按需快照后从单期源码导入。历史尼姆项目用于核对过去的成品与事故证据。新期参数和文字实现从当前制作档案、操作手册与底座取用。

## 生产顺序

导演在策划对话中确认 topic 与 facts（Architect 核查、写分幕）→ Render 制作 preview → 导演确认 review → Render 执行 full、六项验收及归档 → 导演确认 delivery。程序只在这两处停等导演原话，未通过项保留失败状态。单片接手看磁盘记录。职责与返工分流见 [协作流程](PROCESS.md)。

## 4. 制作与发布红线

### 4.2 画面纯净度

正片画面只保留：中部核心动态主画布、极简片名卡、低透明环境微动装饰。**禁止**水印、角标、免责或防御性标注（「示意 · 非按比例」「仅供参考」「教学示例」等）、常驻期数 / 日期 / 学科标签 / 文献小卡、顶部进度条、底部字幕带、矩形外框套娃。事实核查留在后台，交付时归档到 `facts_and_sources.md`。

### 4.3 事实核查（先于一切提示词）

- 每个上屏年份、研究者、文献、数值、公式都必须有**可点击的一手 URL**；一手直接用，二手明确标注；查不到出处就删掉并报告删了什么。
- 一手信源白名单：`Anthropic News` / `OpenAI News` / `Google DeepMind Blog` / `arXiv` / `Hugging Face Daily Papers` / `GitHub Trending` / `Hacker News`；禁止二手聚合稿充当来源。
- **历史档案 / 公版手稿素材前置**：涉及人物肖像、论文手稿、奖项证书、实物照片的，**facts 定稿前完成来源与版权状态判定**并写入 `facts_and_sources.md`；不得画到一半才发现素材不可用。
- **物理 / 力学隐喻自检**：天平轻重方向、斜面倾斜方向、杠杆支点、卡爪开合、滚轮进位等隐喻，必须与命题方向一致；**隐喻画反比画丑更致命**。
- **行情类数据例外（2026-11-20 人工授权）**：选题涉及上市 / 交易 / 股价 / 市值时，允许补充监管披露（SEC EDGAR、交易所公告）、交易所官方报价、权威财经媒体（新华社·新华财经、央视财经、中新经纬、中国日报、路透、CNBC、每日经济新闻等），**仅限行情与法定披露数据**。硬约束：① 至少 **2 家独立来源交叉一致**方可上屏；② 不得用行情媒体充当公司产品 / 技术事实的一手信源，不得标「官方」；③ 必须标注口径（fully diluted / 毛额净额 / 是否含私募配售）；④ 无稳定公开 URL 的聚合行情表不得写入 `facts_and_sources.md`；⑤ 本例外不放松「禁二手聚合稿」通用禁令。
- 避开已被批量模板化的选题（熵增 / 囚徒困境 / 贝叶斯 / 墨菲定律）。

### 4.4 人工卡点（两处，必须停等）

程序强制的人工签字只有 `review` 带声快审验收与 `delivery` 逐条交付确认。**未获确认不得进入下一步，不得以「先跑起来再说」为由绕过。** 前期的 `topic` 选题与 `facts` 事实定稿在策划对话中确认，由工具之外的人负责；`approve --gate topic|facts` 只作历史留痕，不再阻断任何动作，旧单期的记录原样保留。

### 4.5 单条隔离与防上下文膨胀

1. **严禁在同一个长会话中连续渲染多条全片**。
2. 多条任务按编号升序，**逐条在独立隔离上下文**（单条独立 Subagent 或全新会话）执行；每条上下文只加载：现行规范、操作手册和该条的卡片、清单、分幕与交接记录。禁止携带其他条目的脚本、分镜、帧数据。
3. 每完成 1 条：交付物写入对应 `output/` 目录 → 输出当日进度汇总（已完成 / 剩余 / 失败项与原因）→ 释放上下文再开下一条。
4. 任一失败项不得跳过或静默吞掉；其状态保持非完成，列入汇总并等待人工处置。

### 4.6 逻辑角色与本机资源

逻辑角色固定为 Director / Architect / Render / Infra & Verifier，程序卡点固定为 `review / delivery`。角色是职责，不绑定产品名；本机按下述方式分配算力：

- **Codex（Render 主力）**：单期高精视觉动画、专属材质与音色、布局证据与定向返工，每期独立 `/new`。`preview / full` 分步渲染、验收脚本、`tools/mix_bgm.py` 终混与 `tools/decoder_check.py` 硬解均由这一侧执行。
- **WorkBuddy（Infra & Verifier 主力）**：定时采集、磁盘与恢复包运维、轻量基建与文档同步、命令调度（如 `remix` / `verify`）及独立只读复检。**不渲染、不出片、不碰 `output/` 下任何正式视频**，以节省 Codex 额度并隔离渲染上下文。
- 任一方不得代做对方职责；`output/` 正式出片一律由 Render 侧（本机默认 Codex）产出。

### 4.7 发布与合规

- **B 站先过审上线 → 再发抖音 / 小红书**；单账号日发布 **≤2 条**，超出入草稿箱错峰。
- 发布时主动勾选平台「AI 内容声明 / AIGC」选项，保留导出文件的 AI 内容元数据。
- BGM 只用无版权 / CC0 或代码合成；**商单禁止直接使用《We Never (Remix)》**，改用 `sfx_only.wav` + 已授权配乐重混。
- `anything2explainer`（PolyForm Noncommercial）不得用于商单 / 卖课 / B 端交付；Remotion 团队 ≥4 人须购 Company License；不复用真实创作者台标 / 肖像 / 声音。
- 同一提示词批量产出叙事高度近似的视频判「低质矩阵搬运」，禁止；上屏数字全部可回溯 URL。

## 5. 热点借势选题池（`inbox/news/` 的新定位）

### 5.1 每日 08:00 定时任务（不变）

仍按原规则运行：白名单核查 → 写入 `inbox/news/YYYY-MM-DD/{NN_<slug>.md, manifest.json}`，**只入库不出片**；幂等保护，不覆盖已有文件、不重置 `approved` / `done`。执行记忆落在 `.workbuddy/memory/automations/`。

### 5.2 从热点到无声片（唯一合法转化路径）

热点**不能**直接变成口播新闻片，只能作为**借势选题的起点**：

1. 从 `inbox/news/` 的事实骨架里提炼一个「可被图形演明白的机制或反差」（不是复述事件）；
2. 新建 `inbox/evergreen_vibe/NN_<主题>.md`，补全操作手册的选题字段，命题必须**脱离时效也能独立成立**（evergreen：三个月后看仍然成立）；
3. 事实核查按 §4.3 重做一遍（热点稿的口径不能直接沿用），数值与公式全部落到一手 URL；
4. 之后完全按本文生产顺序执行。

> 判定线：**「这条片子在半年后还有没有人看？」** 答否 → 不做。热点只提供「此刻的注意力」，不提供「作品的生命周期」。

### 5.3 `manifest.json` 协议（仅用于热点池）

字段固定：`date`、`cnt`、`items[]`（`id` / `file` / `title` / `track` / `source_urls` / `status`）。`status` 只允许 `pending | approved | done`。
**`approved` 只表示「可进入选题池候选」，绝不触发自动出片**；`cnt` 与磁盘文件数不一致时停止并报告，不得自行补齐、删除或改状态。
